# ECC (affaan-m/ECC): research review, 2026-10-09

Charlie asked: research ECC's "plan, then test until the outcome is right,
then build" workflow; install it, or just follow its principles?

**Checked:** repo `affaan-m/ECC` at ef648e0 (2026-10-01), v2.2.3, MIT
licence, read in a scratch folder (nothing run). Hands Brain rank 1 in
"Claude Code skills & plugins" (seen in 3 weeks; W38 clip at 8:15 shows plan
mode, then the TDD workflow, before building).

**Size:** 68 agents, 293 skills, 94 commands (about 1,000 SKILL.md files in
the repo), 103 MB. The installer runs `npm install` and adds hooks on 7
events (PreToolUse, PostToolUse, Stop, SessionStart, …), which would clash
with our Stop-hook gate.

**Its workflow:** research and reuse → plan and get approval
(`commands/plan.md`) → define "done" first (`skills/eval-harness`) → tests
first (`skills/tdd-workflow`) → smallest change to green → verification
loop with READY / NOT READY (`skills/verification-loop`) → separate
reviewer → commit → learn and save only lessons that score (`commands/learn-eval.md`).

**Ours already:** reuse first, the audit gate, before/after fresh-session
tests, `try-tool`, git on every change. **Basic versions:** plan, define
done, tests first, reviewer per change, scored lessons.

**Verdict: don't install** (it is a coding kit for software teams, its
descriptions alone would swamp Rule 41's smallest context, and its hooks
change every session). **Adopted instead (three ideas, a few lines each):**
1. "Done when" check first, then build: `context/working-rules.md`.
2. READY / NOT READY at the end of big tasks: `context/working-rules.md`.
3. Score a lesson before it becomes a rule or skill: `.claude/skills/audit/content-check.md`.
**Not copied:** "80%+ test coverage", language reviewers, hook-based learning.
